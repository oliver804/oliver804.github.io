Public projects

Two repositories, both MIT

  1. 01

    Local Route Launcher

    v1.2.0 · macOS 13+ · Windows 10/11 · SwiftUI + C# · MIT · released 19 Oct 2026

    Starts a compatible ChatGPT desktop app with your own HTTP proxy, for that launch only — no TUN device, no change to the system proxy or DNS. Settings belong to one process tree instead of the machine, and the interface says so.

    The interesting part was not the feature. It was the diagnostics, the second platform and the packaging: three checks that each state what they did not establish, a Windows edition that shares behaviour but not code, and a release that refuses to publish until both builds pass.

Engineering experience

Practice, not portfolio

These are the areas I have worked in professionally. They are described as practice rather than as projects, because the code is not mine to publish: no employer, client, internal system or dataset is named here, and nothing below is presented as open source.

What can be said honestly is the shape of the problem, the part I owned, and what I would expect to be held responsible for afterwards.

Backend & microservices
Java and Spring Boot services, the contracts between them, and the failure paths that only appear once two services disagree about what a field means. A lot of that work is integration where the other side of the interface is someone else’s and cannot be changed.
Data engineering & platforms
Collection, processing and quality checks, plus the modelling that keeps a number explainable months after it was produced. The pipelines I care about are the ones that fail visibly rather than produce plausible wrong data.
Full-stack delivery
React interfaces built against an API I also own, so the awkward parts of the data model surface in the interface instead of in a ticket three weeks later.
AI-assisted engineering
Coding agents used for review-heavy work: reading an unfamiliar codebase, drafting a change, running the checks. The part that matters is what the review step has to become, not what the model can generate.
Cross-platform delivery
Desktop tools built natively for macOS and Windows — SwiftUI and AppKit on one side, C# and WPF on the other — including packaging, signing limits and the release checks that decide whether something is shippable.
