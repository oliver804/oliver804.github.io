# 个人站主流做法调研（2026-10-20）

目的：把"个人技术站"从"博客排版 + 项目作为其中一个栏目"改成"项目为主、更新频率低也成立"的结构。
判定标准只有三条，来自这个站的真实约束：

1. **一年只更新三四次也不会看起来荒废。**
2. **第一屏回答"这个人做出过什么"，而不是"这个人最近写了什么"。**
3. **结构本身不能是模板。**

调研方法是直接抓取站点正文并读其结构（标题层级、链接分组、元信息使用），不是凭印象描述视觉。
因此下面的结论是关于**信息架构与文案**的，不是关于像素。

---

## 1. 实地观察

| 站点 | 结构事实 | 可以拿走的部分 |
| --- | --- | --- |
| [patrickcollison.com](https://patrickcollison.com/) | 首页没有任何介绍段落、没有头像、没有日期。整页就是 15 个链接的清单（About / Advice / Bookshelf / Culture / Dispatches / …），按主题而非时间排序 | **首页可以只是一份索引。** 索引不会过期，也不需要"最新" |
| [danluu.com](https://danluu.com/) | 单页长列表，约 180 条，只有"月/年 + 标题"，无摘要、无缩略图、无分类；用一条 `* * *` 和 `↑ Public posts` / `↓Patreon posts` 分区 | **极简索引的维护成本接近零**，但完全是"文章站"，不适合以项目为主 |
| [macwright.com](https://macwright.com/) | 首页由多个分区堆叠（Writing / Micro / Photos / Drawings / Reading），每区固定条数 + 日期 | 分区可以有不同形态；但每区都带日期会让整站读起来像 feed |
| [brittanychiang.com](https://brittanychiang.com/)（被多篇 2026 榜单列为"标准答案"） | 固定左栏人像 + 简介 + 导航，右栏滚动内容；项目是少数几条精选 | 固定侧栏如今是**最容易被认成模板**的布局之一，且把人像放在第一位 |
| [tomweightman.com](https://tomweightman.com/)、[arpitbhayani.com](https://arpitbhayani.com/)（Colorlib 2026 榜单） | 首页是"做过什么"的长列表：每条一个产品 + 一句"我负责哪部分" + 一个链接 | **一句职责 + 一个可点链接**比截图网格更有说服力 |
| [taniarascia.com](https://taniarascia.com/)（同上） | 项目页每条给两个链接：源码 + 可试用 | 每个项目给"看代码"和"用它"两个出口 |
| [sive.rs/now](https://sive.rs/now)、[nownownow.com](https://nownownow.com/) | `/now` 页 = 当前在做什么的快照，必须写"最后更新于"；已知失效模式正是**建了页却长期不更新** | 低频率更新的诚实做法：**给日期，不给频率承诺** |

关于 `/now` 的失效模式，[Own Your Web #13](https://buttondown.com/ownyourweb/archive/issue-13) 写得很直白：很多人加了 now 页却忘了更新，于是"now"名不副实。这条直接否掉了我最初"新增 /now 页"的想法——多一个页面就多一个会陈旧的地方。

## 2. "AI 模板感"的可操作清单

2026 年已经有人把这件事整理成可勾选的审计表（[Tech Arion 的 25 条](https://techarion.com/blog/why-ai-websites-look-the-same-how-to-make-claude-design-better)、[Lab Twelve 的 design constitution](https://labtwelve.dev/blog/why-ai-generated-websites-look-the-same)、[Mowgli 的 15 条](https://mowgli.ai/blog/why-ai-built-apps-look-the-same)）。

把三份清单取交集，与本站相关的有：

- 紫色/靛蓝渐变、渐变文字
- Inter / Roboto / 系统字体作为唯一字体，字重只在 400–600 之间
- 居中 hero：胶囊标签 + 大标题 + 副标题 + 两个按钮
- hero 下方三张一样的卡片，同一个圆角、同一个阴影
- 每个标题上方一条全大写小字（eyebrow）
- 给**不是序列**的内容编 01 / 02 / 03
- 每个链接后面都跟箭头
- 每个区块都有相同的上下留白
- 大数字 + 小标签的统计条（尤其是编的）
- 米色背景 + 衬线大标题 + 陶土色强调（新一批"高级感"模板的默认组合）

对照旧版首页，命中的是第 5、6、8 条：**每个区块都有 `01–04` 编号、每个标题上方都有全大写等宽 eyebrow、每段留白等值**。这正是"像杂志/博客"的直接来源——它给了写作栏目和项目栏目同等的版面权重，还给整页加了一条"按期连载"的节奏。

新版据此定的硬规则：

- 全站不再出现编号分区；编号只用在**真的是序列**的地方（作品列表的序号）
- 不再给每个标题配 eyebrow；等宽字只用于**数据单元格**（版本号、日期、平台），不做装饰
- 区块之间**刻意不等距**：作品区的留白是笔记区的两倍以上
- 强调色只用一个，并且只用在"标注"位置（链接下划线、图号、状态点），不做按钮

## 3. 五种主流结构，以及各自对本文约束的代价

| 结构 | 代表 | 一年更新三次会怎样 | 对 Oliver 的适配 |
| --- | --- | --- | --- |
| 博客优先（文章列表当首页） | danluu、多数 Hugo 模板 | 首页永远是 2026 年 10 月那几篇，越看越旧 | ✗ 正是当前问题 |
| 期刊式分区（编号栏目） | 旧版本站、多数"个人刊物"主题 | 版面被四等分，写作和项目抢权重 | ✗ 已证伪 |
| 固定侧栏作品集 | brittanychiang 及大量模板 | 不会过期，但**看起来像求职作品集**，且模板识别度最高 | ✗ |
| 单页作品索引 | tomweightman、arpitbhayani | 仍成立：产品列表不带时间压力 | ✓ 结构可借 |
| 纯索引页 | patrickcollison | 完全成立，但**没有任何展开能力**，只有一个项目时页面会空 | △ 借其"首页即索引"，但要能展开 |

结论：**"单页作品索引"作为骨架，"纯索引"的克制作为语气，"索引条目可展开成项目页"作为深度。**

## 4. 由此确定的新结构

### 4.1 首页（唯一一个真正的入口页）

```
姓名 / 一句话立场            ← 不是 hero，没有按钮，没有居中对齐
状态行：已发布版本 + 本站最后编辑日期

Work                        ← 占全页约 60%
  01  Local Route Launcher   v1.2.0 · macOS 13+ · Windows 10/11 · MIT
      两段：它做什么 / 为什么这样做
      三个出口：项目笔记 / 源码 / 下载
      一张截图（Fig. 1）

  02  This site              手写 HTML · 无构建 · 无 JS
      一段 + 源码链接

      在做但还不能公开的一两句话

Notes                       ← 占全页约 12%，四条一行式链接，无摘要
  标题 ......................... 日期

页脚 title block            ← 文件 / 字体 / 构建 / 最后编辑
```

关键取舍：

- **作品名是全站最大的字**，比姓名大。姓名放在页眉，字号克制。这是"项目优先"唯一真正有效的视觉手段——排版层级就是优先级声明。
- **笔记不带摘要、不带阅读时长、不带分类**。摘要和阅读时长是博客家具；去掉之后，笔记区读起来像脚注，这正是它应有的权重。
- **不写"Latest posts"、不写"Updated weekly"**。只写 `This site: last edited 20 Oct 2026`。低频更新不需要辩解，只需要诚实标注。
- **页脚用工程图纸的 title block**（File / Set / Built / Edited）。它是个人化的、与职业身份同构的、且模板库里没有的东西；同时它把"没有构建步骤"这件事变成了版面的一部分，而不是脚注里的自夸。

### 4.2 其它页面

| 页面 | 变化 |
| --- | --- |
| `/projects/` | 从"Public / Facts / In progress 三段"改为**作品清单 + 一份事实表**；每条给状态、版本、许可证、出口 |
| `/projects/local-route-launcher/` | 内容不动，只重排：下载/源码移到标题下方（作品优先），规格表保留，正文按"问题 → 更窄的问题 → 代价 → 诊断 → 打包"顺序 |
| `/writing/` | 栏目名从 Writing 改为 **Notes**（URL 不变，保留已收录链接），去掉主题计数与 Planned 两段 |
| 四篇笔记 | 外壳重做：`Notes / 项目名` 作为归属行；去掉阅读时长；正文一字不改 |
| `/about/` | 保留原文，去掉编号栏；补一段"为什么不常更新" |
| `404` | 同语言重做 |

### 4.3 视觉语言的调整

| 项 | 旧 | 新 | 理由 |
| --- | --- | --- | --- |
| 纸色 | `#FAF8F3` 奶油 | `#F2F0E9` 灰纸 | 奶油 + 衬线 + 绿色是"独立博客"的默认组合；灰纸更像制图纸 |
| 强调色 | 松绿 `#1D5940` | 标注红 `#9B3A25` | 少一个"博客绿"的暗示；红只用于标注，像校对笔迹 |
| 圆角 | 2px | 0 | 与既定规范一致，且去掉"柔和"的模板感 |
| 编号 | 每段 01–04 | 只有作品序列 | 见第 2 节 |
| 字体 | Newsreader + 系统无衬线 + 等宽 | 同左 | 这套字体是本站唯一不该动的资产 |

字体不动是刻意的：模板感来自结构与配色，不来自一款标题衬线。换字体会丢掉已经建立的识别度。

## 5. 保留与不做的

**保留（本次零改动）**：四个搜索引擎验证文件、`sitemap.xml` / `feed.xml` / `robots.txt` 的存在与作用、四篇笔记的 URL 与正文、项目页 URL、`docs/` 历史文档。

**明确不做**：

- 不加 `/now` 页（见第 1 节失效模式）
- 不加暗色模式（多一个需要维护的状态，且会引入一套新的对比度问题）
- 不加"最近更新"组件或 feed 挂件（没有数据源，也不该有 JavaScript）
- 不编造第三个项目来填版式

## 6. 事实边界

本文引用的站点结构均来自 2026-10-20 当次抓取的正文，未读取其源码或设计稿；"榜单"类文章（Colorlib、SlateGit 等）只用于确认某个布局已被大规模复制，不作为设计依据。文中没有任何关于流量、排名或转化的数字，因为无法验证。
